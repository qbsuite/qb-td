Live Hub mock — protests as the TD would see them; everything runs in memory
Today: a moderator's protest lives only in MODAQ. It rides along in the uploaded game as free text in the match's notes, which the hub never renders — the TD first sees it by opening the downloaded qbj, or in YellowFruit after the .yft export. This mock: a Protests drawer between the status strip and Broadcasts, a count in the status strip, and a marker on each upload row that carries one. Rulings are recorded here and stay on the TO side.
What it would take:
  • The game half of every .qbtd.json already carries MODAQ's structured protests (team, question, word position, answer given, reason). The Worker parses each upload for tiebreaker usage today; protests come out of the same parse and are stored as JSON on the file row, returned with the admin file list.
  • "Can flip the result" and the "if upheld" score are MODAQ's own arithmetic (its protestSwings): the protester gets its neg back, the tossup at its buzz position under the game format's power tiers (super-powers included), and the whole bonus; the team that converted the tossup instead loses its tossup points and the bonus points it earned. A bonus-part protest moves only that part's value. The reader would capture these numbers at upload from MODAQ's game object rather than re-deriving them.
  • Rulings are a small TO-side map keyed by upload + question, saved the way broadcasts are. They are not sent to rooms — the TD reaches the moderator by whatever messaging they already use. Nothing here is public — same rule as the notes the Worker already strips from every public copy.
  • A ruling never edits a score. The moderator applies it in MODAQ and uploads again; the newest upload per round + team pair already replaces the earlier one, so the hub can show when the corrected game has landed.
